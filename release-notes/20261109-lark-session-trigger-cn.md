# Codeflai 更新日志 — 0.35.0 / 2026-11-09

## 概览

现在可以在飞书 / Lark 群里 @Codeflai，让它在你的电脑上直接开一个 Claude 或 Codex 会话去处理问题，处理进度会自动回到群里。

## 新功能亮点

### 在飞书 / Lark 群里派活

- **需求背景：** 同事在群里报了一个 bug、贴了截图，过去你得自己把文字和图片搬进 Codeflai，再新建会话交代一遍；人不在电脑前时，这件事只能等。
- **功能描述：** Codeflai 在你的群里是一个机器人。回复（引用）那条 bug 消息，@Codeflai 并写上项目名和要做的事，例如「@Codeflai 用 claude 在 codeflai 项目修复这个 bug」。你的电脑上随即开出一个新会话，被引用的文字和图片会作为参考资料交给 agent。
- **使用场景：**
  - 同事在群里报问题，你顺手转给 agent 处理；
  - 人不在电脑前，用手机在群里给家里或办公室的电脑派活。
- **操作路径：** 设置 → **Lark**。填入应用的 App ID 和 App Secret，打开开关并保存；点 **Bind me** 拿到一个 6 位绑定码，在飞书里手动输入 @ 选中机器人，后面跟上「绑定 + 绑定码」发出。机器人回复「已绑定」就可以用了。

**机器人会在群里回复这些内容（都挂在你发的那条指令下面）：**

- 会话开起来时：用的哪个项目、哪个 agent、哪个分支；
- agent 每跑完一轮：改了哪些文件；没改动时提醒你它可能在等你回复；
- 会话结束时：「会话已结束」和最终改动；
- 出问题时：找不到项目、同时写了 claude 和 codex、没写要做什么、本机没装对应的 agent、你不在白名单里，都会直接说明原因。

**其他用法：**

- **指定 agent：** 指令里写 `claude` 或 `codex`，不写默认用 Claude。
- **指定 skill：** 指令以 `/fast-do` 这样的 skill 开头，会把它交给 agent 执行，例如「@Codeflai /fast-do 修复 codeflai 的登录 bug」。
- **邀请同事：** 绑定后点 **Add teammate** 生成一个绑定码交给同事，同事照同样的方式发出即可。同事发起的会话，标题前会带上他们的名字。

## 特别说明与指引

- **每个任务都在独立的 worktree 和分支里进行**，不会动你正在编辑的项目目录。不是 Git 仓库、或者还没有任何提交的项目会被直接拒绝。
- **Codeflai 不会替你提交、推送或开 PR。** 想让 agent 做这些，在指令里写明。
- **只有白名单里的人能派活。** 身份按飞书账号识别，与消息里写的名字无关；白名单只能在你电脑上的设置里修改，群里改不了。白名单里的人发起的会话会以免确认模式运行，等于能在你的电脑上执行命令，只添加你愿意交出终端的人。
- **飞书开放平台需要开通这些权限：** `im:message.group_at_msg:readonly`、`im:message:readonly`、`im:message:send_as_bot`、`im:resource`、`contact:contact.base:readonly`、`contact:user.base:readonly`。两个 contact 权限都要开，否则白名单里显示的是一串 ID，而不是名字。另外在「事件与回调」里选择长连接并订阅 `im.message.receive_v1`。每次修改权限或事件后，都要发布一个新版本的应用才会生效。设置页里列有完整清单。
- **`im:message.group_msg` 是可选的。** 这个权限需要管理员审批，被拒也不影响主要功能：引用消息和截图照样能读到。它只用于 Codeflai 重新连上后补查离线期间的群消息。没有它时，飞书自己也会把错过的消息重新送来（实测一条离线 65 分钟的消息，在重新连上约 10 分钟后送到），这些消息会被回复「请重新发送」，不会执行。
- **Codeflai 关着时发来的指令不会执行**，统一回复「这条消息发出时 Codeflai 未运行，没有执行，请重新发送」。
- **一个机器人只连一台电脑。** 不要在两台电脑上填同一个 App ID，否则两台都会回复。同事发的指令也是在你的电脑上运行。
- **「跑完一轮」的回复靠 Codeflai 窗口判断**，窗口没开时不会发这条回复，会话本身照常运行。
- **升级到这个版本时，正在运行的会话会重启一次**，并自动续接上次的对话（Claude 用 continue，Codex 用 resume）。这是后台会话进程换代导致的，只发生在这一次升级。
