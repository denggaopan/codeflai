# Lark 同事绑定项目（设计）

日期：2026-11-16

## 意图

同事 @ 机器人发指令时不用再写项目名：owner 在 Settings 点 Add teammate 时选定一个项目，这位同事之后的指令都在这个项目里开会话。绑定是**限制**，不是默认值：这位同事只能用这个项目。

## 目标 / 非目标 / 反目标

- 目标：Add teammate 旁有项目下拉；绑定了项目的同事发指令不需要项目名；白名单列表里能看到每位同事绑定的项目。
- 非目标：在列表里直接改已绑定的项目（要改就移除后重新添加）；给 owner 绑定项目（owner 不受限，仍要在消息里写项目名）；一位同事绑定多个项目。
- 反目标：任何情况下，受限的同事在绑定项目之外开出会话，或把话打进别的项目的会话。读不懂、找不到的限制一律按拒绝处理，不能退化成「不受限」。

## 方案

1. **项目挂在成员记录上（选定）**：配对码带可选的 `projectId`，兑换时写到成员记录的 `projectId`。回滚到旧版本时，旧版的 `larkMemberSchema` 是 `strictObject`，认不出新字段，整份 Lark 配置会被当成空的（机器人停用），方向是拒绝。
2. 顶层另存一张 `openId → projectId` 的表：旧版本读得了配置，但看不见限制，同事在旧版本下变成不受限，而且旧版本一写配置就把这张表丢掉。方向是放行，不符合反目标。
3. 另开一个文件存绑定：同样在旧版本下放行，还多一个要保持一致的文件。

选 1。代价写进 release notes：升级后回滚到旧版本需要重新配置 Lark。

## 行为

- **Settings**：有 owner 之后，Add teammate 按钮旁有一个项目下拉，列出当前项目，第一项是「所有项目」（不限制，与现在的行为相同，也是默认选中项）。配对码面板和白名单每一行都显示绑定的项目名；项目已被移出列表时显示「项目已移除」。
- **IPC**：`lark:start-pairing` 的请求多一个可选的 `projectId`。只对 `role: 'member'` 有意义，`owner` 带了它就拒绝；主进程校验它是当前已注册的项目。
- **存储**：`pairing.projectId?`、`member.projectId?`。兑换成员码时把码上的 `projectId` 写进成员记录；已在白名单里的同事兑换新码，绑定按新码覆盖（新码不带项目就变回不受限）。owner 兑换成员码时维持现状：码作废，owner 不变。旧配置没有这个字段，照常解析，等于不受限。
- **发指令**：受限的同事发来的消息**完全不做项目名匹配**，直接用绑定的项目；消息里出现的其他项目名只是任务文字。agent 与 skill 的解析不变。指令只剩空白仍回 `请写出要做什么`。
- **绑定的项目不在了**：回复 `你绑定的项目已不在 Codeflai 中，请联系管理员重新添加`，不开会话。
- **跟帖**：受限的同事回复另一个项目的会话对话时，回 `没有权限`，不把内容打进那个会话。
- 不受限的成员与 owner：行为一字不变。

## 留给实现者

- `parseLarkCommand` 怎样接收「已定项目」（多一个参数或拆出一个函数），以实现最简单为准。
- 下拉与两处项目名的具体样式，沿用 Settings 现有的 `settings-select` 与 hint 样式。
- 三个字典的文案；`lark-store`、`lark-command`、`lark-bridge-service`、`LarkSettings` 的单测，以及 `FileLarkClient` 的 e2e 里加一条「绑定项目的同事不写项目名也能开会话」。
